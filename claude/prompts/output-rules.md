# OUTPUT RULES

General rules:
- Be concise by default
- Be practical over verbose
- Prefer implementation over discussion
- Use exact file paths
- Keep token usage efficient
- Do not rewrite unrelated files
- Do not overengineer
- Reuse existing project patterns
- Use mock data first unless told otherwise

Clarification rules:
- If the request is clear, proceed directly
- If key details are missing, ask at most 3 concise questions
- Group questions together
- If 80% clear, proceed with brief assumptions

Planning rules:
- Before coding, provide a short implementation plan
- Keep the plan brief and file-oriented
- After plan, write code only for the requested scope

Frontend rules:
- Prefer modular reusable components
- Follow the agreed route and folder structure
- Keep UI clean, light, modern, and professional
- Default to responsive behavior
- Favor maintainability over cleverness
